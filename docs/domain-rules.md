# 领域边界

贯通精品钢生产、固废资源化、制氢和环保指标的可追溯数据链。

## 数据对象

服务（`src/steel_ledger.py`）记录以下对象，构成同一批生产数据的完整链路：

- 产线 `ProductionLine` 与工序 `ProcessStep`（炼铁、炼钢、热轧、焦炉煤气 PSA 制氢等）
- 原料批次 `MaterialBatch`（以 `parent` 串联投入链）
- 精品钢规格 `ProductSpec` 与产品批次 `ProductBatch`（关联规格与原料批次）
- 固废处理记录 `WasteRecord`（废物类型、来源工序、合作单位、去向、回用工序）
- 工业副产氢记录 `HydrogenRecord`（气源、氢量、去向、合作单位）
- 环保指标口径 `EnvTarget`（指标类别、单位、方向、允许区间）
- 参与方 `Actor`（车间、环保、工艺/算法、管理、能源、合作单位）

## 角色与职责分离

| 角色 | 权限 |
| --- | --- |
| 车间操作人员 `operator` | 提交测量、申报事件与用途变更 |
| 环保人员 `env` | 环保类指标复核；节能成果会签方之一 |
| 工艺/算法负责人 `process` | 质量与节能类指标复核；节能成果会签方之一 |
| 管理人员 `auditor` | 数值冲突人工核对、冻结班次、发布报表 |
| 合作单位 `partner` | 参与副产物去向确认与改用途申报 |

- 节能成果（`energy_saving`）必须工艺/算法与环保**双签**，任一方不能独自确认，会签完成前不得结算。
- 测量提交人不得复核同一指标。
- 数值冲突只能由管理人员裁决，车间与环保均无权自行处理。

## 班次冻结与口径

- 班次开启时锁定当前**计算口径版本**；口径版本只能递增、已发布版本不可修改。
- 口径升版只影响升版后开启的班次，不回溯历史。
- 班次冻结后数据来源不可变：完全一致的重复上传幂等放行，任何新值必须走事件更正；存在未决冲突时禁止冻结。

## 上传、幂等与冲突

- 测量以幂等键（班次 + 测点）去重：键存在且测点、数值、单位完全一致 → 原样确认。
- 同键数值不一致 → 不覆盖原数据，生成 `Conflict` 进入人工核对队列，关联指标置为 `disputed`，不得冻结、确认或结算。
- 管理人员裁定采信既有值（`resolve existing`）、采信新值（`resolve incoming`）或双方驳回（`reject`，该测点无指标）。裁定结果与处理人留痕。

## 局部影响传播

设备检修、检测迟到、副产物改用途只作用于标注的相关测点：

- 旧指标标记为 `superseded` 并以新版本承接重算，血缘不断、历史不删；已结算的旧结算标记冲销，待新版本重新会签结算。
- 同班次未被标注的指标、确认状态与结算不受影响。
- 副产物改用途同步更新固废/制氢处理记录的去向与合作单位。

## 报表不可重写与追溯

- 报表发布时固化覆盖班次、口径版本、全部已确认指标及会签人，并生成指纹；之后的事件更正、复测、口径升版均不改变已发布内容，报表编码不可重复使用。
- `trace(metric_id)` 从任一绿色指标回溯：班次与口径 → 测量与提交人 → 原料批次链、工序、固废/制氢/产品处理记录 → 会签责任确认 → 冲突裁定记录。
- `consistency_check(shift)` 显式断言同源测量派生的产量、固废利用、副产氢与环保绩效数值一致，避免按车间报表分别汇总造成相互矛盾。

## 资料约束

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。
