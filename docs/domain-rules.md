# 领域边界

贯通精品钢生产、固废资源化、制氢和环保指标的可追溯数据链。

## 数据链

产线 → 工序 → 原料批次 → 班次（测量 / 精品钢批次 / 固废记录 / 制氢记录）→
指标快照与报表 → 合作单位结算。每个节点都带有责任主体，指标可沿链双向追溯。

## 实体

- 产线、工序（属于产线，按工序顺序组织）
- 原料批次（铁矿石、废钢、焦炭、焦炉煤气等，挂到投入工序）
- 精品钢规格与产品批次（合格判定支撑合格率）
- 班次（产线 + 日期 + 班次号，冻结时固化数据来源与口径版本）
- 测量（原始指标，车间提交）
- 固废处理记录、焦炉煤气制氢记录（含合作单位与初始去向/用途）
- 设备检修登记、检测迟到登记、副产物改用途登记
- 冲突单（数值冲突人工核对）、口径版本、报表、结算

## 指标与复核策略

| 指标 | 类别 | 来源 | 复核角色 |
| --- | --- | --- | --- |
| 粗钢产量 | production | 车间测量 | 管理人员 |
| 吨钢综合能耗 | energy | 车间测量 | 环保人员 + 能源管理人员 |
| 二氧化硫 / 颗粒物浓度 | env | 车间测量 | 环保人员 |
| 工业固废产生量 | waste | 车间测量 | 环保人员 |
| 精品钢合格率 | quality（衍生） | 产品批次 | 随报表 |
| 碳减排量 | energy（衍生） | 能耗、产量按口径计算 | 随报表 |
| 固废资源化利用率 | waste（衍生） | 固废记录当前去向 | 随报表 |
| 焦炉煤气副产氢产量 | energy（衍生） | 制氢记录 | 随报表 |

工艺算法人员不出现在任何复核角色中，因此不能独自确认节能成果；提交人
不能复核本人提交的数据；复核操作本身幂等。

## 关键规则

1. **班次冻结**：冻结要求所有测量与处理记录完成复核、冲突全部核对、
   迟到登记已被补录消费，且至少有粗钢产量。冻结后拒绝任何原始数据写入，
   并记录当时口径版本。
2. **幂等提交**：同一幂等键重复提交返回既有结果；换键但内容完全相同同样
   幂等；同键不同内容直接拒绝。
3. **数值冲突**：同班次同原始指标出现不同值，双方测量同时挂起并生成冲突单，
   只能由管理人员人工核对；选定值回到待复核状态重新走完整复核，落败值作废。
4. **异常局部影响**：
   - 设备检修只在登记的相关指标上打标（能耗标记会传播到碳减排）；
   - 检测迟到先登记、再以迟到补录提交，只标记该指标；
   - 副产物改用途只改变相关衍生指标的后续视图，并作废旧结算，
     原始记录保持不变。
5. **口径与报表不可变**：口径整体版本化、只能递增发布；报表按班次冻结的
   口径版本生成快照与指纹。口径变更或改用途都不修改已发布报表；需要反映
   新事实时发布新报表，旧报表与旧结算保留留痕。
6. **仅追加事件**：所有状态由 JSONL 事件回放得到，事件带序号与哈希链；
   任何对历史事件的改写都会在回放校验时暴露。

资料版本只能递增。参与方、事实和约束均不能为空，示例不得包含真实个人信息、账号或凭据。
